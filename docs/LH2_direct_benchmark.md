# QES LH2 근사 결합 구현과 SLABx-LH2 직접 비교

2026-11-07. **연구용 결합을 구현해 실제 실행했지만, 정확도 개선에는 실패했다.** 3차원 풍향·풍속·장애물 처리는 유지됐다. 현재 구현으로 SLABx-LH2를 대체하거나 검증된 위험거리를 제시할 근거는 없다.

## 실제 구현

QES 2.3.1 원본 C++ `ParticleModel`에 선택적으로 켜는 `LH2Coupling`을 추가했다. QES-Winds의 질량보존 바람장, 건물 경험식, QES-Plume의 3차원 stochastic GLE와 벽 반사는 계속 사용한다. 별도 가우시안 모델을 QES라고 부른 것이 아니다. 기존 `gas-qes:2.3.1` 이미지는 유지하고, 연구 이미지는 `gas-qes:lh2-prototype`으로 구분한다.

- 수소 입자 질량을 바람 격자에 집계한다. 질량 단위는 QES의 g에서 kg으로 변환한다.
- 국소 수소 질량농도에서 일정 압력의 단열 평형 혼합 온도·밀도·기상 수소 체적분율을 조회한다. LH2 잠열 445 kJ/kg, 비열 근사 14.3 kJ/(kg K), 액체 밀도 70.8 kg/m³, 끓는점 20.37 K를 사용한다. 초기 기상/액상 비율에 따른 엔탈피 차이도 포함한다.
- 공기 비열은 1.005 kJ/(kg K), 혼합물 기체상은 이상기체 근사다. 미량 수분 응축·동결의 잠열을 근사적으로 포함한다. 응축수의 질량 하중은 생략했다. 상대습도 75%는 측정값이 아니라 두 모델에 공통으로 준 가정이다.
- 셀 내 수소 질량으로 가중한 추가 운동량을 입자들이 운반한다. 부력 가속도는 `g*(rho_air-rho_mix)/rho_air`, 항력은 `Cd=0.5`, 길이 1 m인 암시적 이차 항력이다. 이 길이는 실험에 맞춰 선택한 값이 아니며 보편 상수가 아니다.
- 수평 방출은 측정 유량과 액체 노즐 단면으로 계산한 액체 속도를 초기 동향 운동량으로 준다. 아래쪽 방출은 지면 충돌 후 수직 운동량이 소실된 점 소스로 근사한다. 완전한 플래싱 제트 운동량 모델이 아니다.
- 30개 센서마다 2×2×0.2 m 상자의 순간 수소 질량을 집계하고, 매 시간 단계에서 체적분율로 바꾼 뒤 평균한다. 비선형 변환의 평균과 평균농도 변환을 혼동하지 않는다. 같은 상자를 SLABx에서도 3×3×3 구적점으로 공간 평균한다.
- `QES_RNG_SEED`를 추가해 난수 시드를 명시할 수 있게 했다. 소스는 결정론적 점 소스이며, OMP 스레드는 4개로 고정했다.

셀에 입자들을 집계해 집단적인 온도·밀도·부력을 계산한다는 구성은 [heat-carrying Lagrangian 연구](https://asr.copernicus.org/articles/21/19/2024/)를 참고했다. 해당 논문은 가열 공기의 검증이며 LH2 검증 논문이 아니다. 이번 구현의 수소 열역학·항력·소스 처리는 자체 근사이므로 논문의 검증 성능을 물려받는다고 주장하지 않는다.

**구현하지 않은 물리:** 지면·콘크리트와의 비정상 열전달, 액체 풀의 질량·에너지 재고, 별도 액적의 크기·기화율·비산, 노즐의 압축성 2상 플래싱, 공기 액화·산소/질소 상변화, 연소. 밀도에 의한 압력장을 다시 풀지 않으므로 중력류의 횡방향 퍼짐과 건물 주변 밀도 피드백도 완전히 해석하지 않는다. 이는 완전한 가변밀도 CFD가 아니다.

## 같은 자료로 맞춘 비교 조건

FFI 공개 보고서 Appendix A의 7개 시험, 농도 센서-시험 기록 **210개**를 사용했다. 온도 616개 기록은 확보돼 있지만 이번 농도 오차 산정에 넣지 않았다. 보고서 평균과 모델 시간평균을 비교했으며 시간최대값과 섞지 않았다. 원 보고서의 농도는 직접 수소 계측값이 아니라 산소 센서의 산소 결핍에서 환산한 값이다. 기상 평균풍은 보고서에 명시된 10 m 높이 센서 값이다.

센서의 `R, B, z`는 `east=R*sin(B), north=R*cos(B)`로 변환했다. 기상 풍향은 바람이 오는 방향이며, SLABx 좌표로 옮길 때 180°를 더했다. Test 2의 9.010/11.043/30 m 배치도 그대로 사용했다.

**실험 시계열을 완전히 재현한 비교는 아니다.** 원시 풍향·풍속 시계열과 상세 밸브 운전 이력이 없어서 정상 평균 기상으로 계산했다. QES는 공통 100초 준비 계산 후 보고서의 평균길이 동안 계속 방출했다. 원 보고서의 절대 시작·끝 시간과 정확히 같은 과도 상태는 아니다. SLABx는 같은 평균길이를 사용하는 정상 plume 후처리다. Test 5/6의 농도표는 점화 전 구간이지만, 재시작·점화와의 상세 과도 효과는 복원하지 않았다. 이들 시험을 뺀 150개 기록도 별도로 집계했다.

SLABx 비교 대상은 [공개 저장소](https://github.com/lyullee/slabx-lh2)의 slabx 1.0.8 / slabx-lh2 0.2.0, 기존 `HorizontalJet + plume_width_coupling + water_ice` 경로다. 기존 6개 시험 예제를 7개 조건과 센서 평균 비교로 확장했다. 이 공개 경로는 아래쪽 방출에도 HorizontalJet 소스를 사용하므로 실제 소스 방향을 충실히 재현한다고 볼 수 없다. 최신 비공개 연구 capsule의 v1162/v1165 선택 경로를 재현한 것이 아니다. 저자가 보고한 RMSE 0.132241 vol%와 아래의 공개 경로 결과는 다른 구성이다.

## 실측 농도 오차와 계산시간

농도 오차 단위는 **체적농도 백분율의 차이, 즉 percentage point**다. 예를 들어 관측 4 vol%, 예측 3 vol%면 오차는 1 percentage point다.

| 모델 | MAE | RMSE | Bias | 양의 관측값 FAC2 | 시험당 시간 범위 | 시험당 평균 시간 |
|---|---:|---:|---:|---:|---:|---:|
| QES 수동 추적가스 대조 | 0.6886 | 1.8800 | −0.3866 | 16.5% | 4.0–11.9 s | 7.15 s |
| QES + LH2 연구 결합 | 0.7117 | 1.9717 | −0.7085 | 10.1% | 12.7–48.4 s | 24.41 s |
| 공개 SLABx-LH2 비교 경로 | 0.7368 | 1.9829 | −0.5429 | 12.9% | 0.52–0.68 s | 0.592 s |

QES 결합은 공개 SLABx 경로보다 전체 RMSE가 약 0.6% 낮지만, **기존 QES보다 RMSE가 약 4.9% 커졌다.** 음의 bias가 커졌으며 고농도 과소예측이 심하다. 210개가 독립 실험 210회인 것은 아니다. 7개 시험 단위의 탐색적 paired bootstrap에서 RMSE 차이(QES 결합−SLABx)의 95% 구간은 −0.0756~+0.0167로 0을 포함한다. 이 결과로 우월성을 주장할 수 없다.

점화 없는 Tests 1/2/3/4/7만 쓰면 RMSE는 수동 QES **0.7810**, QES 결합 **0.9770**, 공개 SLABx **1.0237**이다. 이 경우도 결합이 기존 QES를 개선하지 못했다.

특히 전체 일치율만 보면 위험한 농도 누락이 숨는다:

| 실측 평균 기준 | 실제 양성 수 | 수동 QES 검출/누락 | QES+LH2 검출/누락 | 공개 SLABx 검출/누락 |
|---|---:|---|---|---|
| ≥2 vol% | 24 | 7 / 17 | **2 / 22** | 6 / 18 |
| ≥4 vol% | 9 | 5 / 4 | **2 / 7** | 3 / 6 |

이는 센서 시간평균의 분류이며 순간 LFL 경계의 검증이 아니다. 현재 결합으로 위험농도 범위를 신뢰성 있게 예측했다고 볼 수 없다. 수동 모델의 숫자가 더 낫다고 해서 수동 가스 가정이 LH2에 물리적으로 적절하다는 뜻도 아니다.

시간은 동일 PC(i5-10400F, GTX1660 SUPER), 같은 Linux Docker 환경에서 측정했다. QES는 GPU wind solver와 CPU 4-thread 입자 계산이며, 240×240×25 m 영역, 바람 격자 2×2×0.5 m, dt=0.2 s, 초당 입자 100개, 물리시간 220–900 s다. 바람·난류·3D 농도장 NetCDF 출력과 센서 집계를 포함하고 Docker 시작·컴파일은 제외했다. SLABx 시간은 물성·적분·210개 중 해당 시험 30개 센서 상자 후처리를 포함한다. SLABx는 같은 전체 격자장을 풀지 않으므로 처리량이 같은 속도 경쟁으로 해석하면 안 된다. 일반 CFD와 동일 실험의 계산시간은 측정하지 않았으므로 CFD 대비 배수를 제시하지 않는다.

## 수치 민감도와 3D 기능 확인

FFI Test 4에서 다음을 실제로 추가 실행했다. 오차를 줄이는 설정을 골라 본 결과표를 교체하지 않았다.

| 변경 | QES+LH2 RMSE | 시간 |
|---|---:|---:|
| 기준 | 1.7922 | 19.93 s |
| 다른 시드 1 | 1.8406 | 20.14 s |
| 다른 시드 2 | 1.8219 | 19.93 s |
| 입자 100→400개/s | 1.7346 | 31.62 s |
| 수직 격자 0.5→0.25 m | 1.7477 | 37.85 s |
| 시간 간격 0.2→0.1 s | 1.7662 | 35.19 s |

세 시드, 입자 수, 시간 간격, 수직 격자의 제한된 확인이다. 수평 격자까지 포함한 완전한 수렴 검증은 아니다. 수치 변화와 모델 간 차이의 규모를 고려해 순위를 확정하지 않는다.

풍향을 남풍으로 변경, 풍속을 절반으로 변경, 10×10×5 m 건물 추가 사례도 실행했다. 3차원 농도장이 각각 달라졌으며 19.3–21.5초에 완료됐다. 기준 대비 센서 예측의 RMS 변화는 각각 1.4054 / 0.4413 / 1.3625 percentage point다. **이는 기능 확인이며, FFI 현장에 이 건물이 있었다거나 장애물 조건의 LH2 정확도가 검증됐다는 의미가 아니다.**

수치 확인: 22개 QES 실행의 이탈 입자는 모두 0개였다. 주 비교 바람장의 u/v/w는 유한값이다. 단열 에너지 잔차 최대 2.65e−8 J/kg, 질량농도 조회표 단조성·상분율 범위 등 7개 점검을 통과했다. C++의 실제 결합 헤더로 입자 1개를 100개로 나눈 경우 동일 부력, 고밀도 혼합물 하강, force-off 세 가지 한계조건을 확인했다. 조회표를 사용하는 결합 주 계산에서 80 K 미만 셀의 수소 질량-시간 비중 및 조회표 초과 비중은 0이었다. 이 사실은 실제 노즐 근처 저온 영역이 사라졌다는 뜻이 아니라, 그 영역을 이 격자에서 해상하지 못했다는 뜻이다.

## 판단과 다음 개발 우선순위

**장애물 해석 기능과 수십 초 실행은 확보했으나, 원하는 정확도 향상은 확인되지 않았다.** 원인 후보는 지면 충돌·풀·열전달·플래싱 운동량의 미해상, 밀도 압력장의 생략, 평균 기상만 사용한 좁은 plume, 단순 항력 폐쇄다. 각 원인의 기여도는 이번 자료만으로 분리하지 못했다.

다음 개선은 수용체 농도에 맞춰 항력 계수를 조정하기보다, 측정 가능한 소스 질량·엔탈피·운동량과 지면 열전달을 보존하는 근거리 모델, 중력류 압력 보정, 실제 바람 시계열 결합에 두어야 한다. 검증은 FFI와 독립인 PRESLHY 실험에서 실시해야 한다. 확보한 PRESLHY trial 10은 센서 포화·배치·운전 시계열 정리가 필요해 이번 우열 판정에는 사용하지 않았다. 여러 데이터가 이미 있다는 이유로 미완료 조건을 검증 결과에 섞지 않았다.

## 파일과 재실행

- 구현: `src/qes_lh2/LH2Coupling.h`, 적용 스크립트 `scripts/patch_qes_lh2.py`.
- 재현 입력·고정 조건: `data/cases/lh2/`, `results/lh2_benchmark/protocol.json`.
- 센서별 예측: `results/lh2_benchmark/sensor_predictions.csv`.
- 지표/민감도/확인: `metrics.json`, `sensitivity.json`, `physics_checks.json`, `verification.json`.
- 그림: `comparison.png`, `wind_obstacle_checks.png`.
- 각 실행: `results/lh2_benchmark/test*/`의 XML 원본에 대응하는 command, execution.json, run.log, receptors.csv, 3D NetCDF.

PowerShell, 프로젝트 루트에서:

```powershell

.venv\Scripts\python.exe scripts/benchmark_lh2.py --prepare

docker run --rm --gpus all --mount "type=bind,source=$((Get-Location).Path),target=/work" gas-qes:lh2-prototype python3 scripts/benchmark_lh2.py --suite
docker run --rm --gpus all --mount "type=bind,source=$((Get-Location).Path),target=/work" gas-qes:lh2-prototype python3 scripts/benchmark_lh2.py --slab
docker run --rm --gpus all --mount "type=bind,source=$((Get-Location).Path),target=/work" gas-qes:lh2-prototype python3 scripts/benchmark_lh2.py --extras
.venv\Scripts\python.exe scripts/analyze_lh2_benchmark.py
.venv\Scripts\python.exe scripts/analyze_lh2_sensitivity.py
.venv\Scripts\python.exe scripts/check_lh2_physics.py
```
